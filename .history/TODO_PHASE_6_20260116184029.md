# Phase 6 — TUI MVP Implementation

## Goal
Implement a minimal TUI with message-driven architecture using mikomn's panes, widgets, and command palette.

## Current State (After Phase 5)
| Component | Status | Notes |
|-----------|--------|-------|
| `app.py` | ✅ Base | Extends `BaseTuiApp` with theme cycling |

| `widgets/` | ⏳ Empty | Needs widget implementation |

## Implementation Plan

### Phase 6.1: Message Schema
Define messages/intents for TUI operations:
- `BackupIntent`, `ArchiveIntent`, `RestoreIntent`, `TransferIntent`
- `NavigateToScreen`, `ShowCommandPalette`, `ConfirmAction`
- `ServiceResult` - response from service layer

### Phase 6.2: Panes (using mikomn)
Create TUI panes:
- `SidebarPane` - Navigation sidebar with menu items
- `LogPane` - Run logs with streaming and filtering
- `StatusPane` - Status bar with theme info
- `HeaderPane` - App header with title

### Phase 6.3: Screens
Create operation screens:
- `BackupScreen` - Backup operations
- `ArchiveScreen` - Archive operations
- `RestoreScreen` - Restore operations
- `TransferScreen` - Transfer operations
- `ToolsScreen` - Utility tools

### Phase 6.4: Widgets
Create reusable widgets:
- `OperationCard` - Display operation summary
- `StatusIndicator` - Show operation status
- `KeyBindings` - Footer with key hints

### Phase 6.5: Command Palette
Define Command config:
```python
commands = [
    Command(id="backup", title="Backup", group="Operations"),
    Command(id="archive", title="Archive", group="Operations"),
    Command(id="restore", title="Restore", group="Operations"),
    Command(id="transfer", title="Transfer", group="Operations"),
    Command(id="theme", title="Cycle Theme", group="Settings"),
]
```

## Acceptance Criteria
- [ ] No business logic in UI (only message dispatch)
- [ ] Theme cycling works via 't' key
- [ ] Command palette accessible via Ctrl+P
- [ ] Platform layout adapts to terminal size
- [ ] Widgets emit messages, not perform actions
- [ ] TUI works without modifying core
