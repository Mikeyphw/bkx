# BR35 — Release Packaging, Signing and Native Runtime Seal

**Overlay 15 of 16** in the BKX BR21–BR36 remediation roadmap.

## Purpose

BR35 closes U31: release packaging, signing, native runtime and build-input findings. It turns BKX Android deployability from a set of source-text promises into staged, artifact-oriented validation that can qualify the actual release APK.

## Fix scope

- Generated Go runtime builds are stamped with a real Git revision through `BKX_BUILD_COMMIT`; `Commit=dev` is rejected during Android runtime packaging.
- The Gradle Go-runtime generation task now models `go.mod`, `go.sum`, `internal/version/version.go`, source directories, the runtime build script, and the resolved commit as tracked inputs.
- Android `versionCode` is moved to a non-colliding `major * 1_000_000 + minor * 1_000 + patch` lane with bounded semantic-version components.
- Release APK builds enable R8 minification and resource shrinking with explicit BKX keep rules for Tasker/Locale, libsu, root-service, automation, and schedule entry points.
- Release lint is part of the validation lane; BR35 adds explicit `lintEmbeddedRelease` and `lintLiteRelease` coverage alongside edition-specific debug lint.
- The release manifest gate now verifies the merged release manifest generated by AGP, not only source `AndroidManifest.xml` text.
- Native 16 KiB APK verification is moved out of the cheap preflight group and into the package phase, where it can depend on actual APK outputs.
- Release gates are split into staged tasks: `bkxAndroidReleasePreflightSeal`, `bkxAndroidReleasePackageSeal`, `bkxAndroidReleaseInstrumentationSeal`, and `bkxAndroidReleaseFinalSeal`.
- The device qualification helper accepts `--release-apk` and `--android-test-apk`, installs the exact artifact, records package evidence and APK SHA-256, then runs the existing visual/root instrumentation lane against that installed package.
- GitHub CI now has an Android release-packaging job with Java 21, Gradle 9.7.1, SDK 36, Build Tools 36.0.0 and NDK 29.0.14206865.
- Android dependency locking is enabled for all configurations so resolved release inputs can be generated and committed with `gradle --write-locks`.
- Split archives now publish `.bkx-parts.json` sidecar manifests containing part count, total bytes, part names, sizes and SHA-256 hashes; readers fail closed when a present manifest is invalid or a part is tampered.
- Human typed-error collections render as JSON arrays/objects instead of Go-native formatting such as `[a b]`.

## New gate task

```text
:app:verifyBkxReleasePackagingSigningNativeRuntimeSeal
```

This task verifies the BR35 source/doc/test markers and is wired into `bkxAndroidReleaseSeal`. Full execution should be deferred to BR36/final gate validation.

## REL-03 edition migration addendum

The historical BR35 staged-gate promises still apply to both release editions.
`verifyBkx16KbNativePageSizeContract` aggregates exact-APK checks through
`verifyBkxEmbeddedRelease16Kb` and `verifyBkxLiteRelease16Kb`; do not replace
them with a generated-directory or Go-only source inspection. Both release
manifests, lint lanes, JVM suites and `verifyBkxEditionApkContents` are
required. No CI hosted artifact is a locally LIFE-signed release.
